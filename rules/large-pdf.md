# 大型 PDF 完整讀取策略

目的：不能因 Drive 連接器或單檔大小限制直接略過任何當次來源，也不能把「請使用者自行分割」當成第一個解法。

## Fallback 順序

1. **Drive 索引文字**：先嘗試取得 provider 已解析的完整可讀文字；若只有摘要、片段或無頁面覆蓋，不算完整。
2. **原始檔下載**：
   - 檔案在目前 connector raw-download 上限內時，直接下載原始 PDF 到本機工作區。
   - 若超過 connector 上限，檢查是否存在可用的**已驗證身分串流或 HTTP Range/分段下載通道**；若可用，直接串流完整原檔到本機，不要求一次載入記憶體。下載完成後先核對檔案大小/雜湊或可驗證 metadata，再切頁處理。
   - connector 回報 413/size limit 只代表該通道失敗，不代表來源不可讀。
3. **同內容可讀副本**：在同一學期資料夾及可存取 Drive 中搜尋同一原檔的分卷、壓縮版、逐人分檔或其他可驗證的衍生副本；必須能對應回原檔且覆蓋完整。
4. **Work/瀏覽器路徑**：若 default connector 與直接串流都無法取得 bytes，使用可用的 Work/Computer/Cloud Browser 下載原檔，再用本機工具按頁數或檔案大小切成多份，逐份轉文字並建立 page map。
5. **人工前處理才是最後手段**：只有前述路徑都不可用時，才請使用者提供分割/壓縮副本。建議每一分檔小於 200 MiB，並以原檔名加 `_part01`、`_part02` 命名，保留原頁順序。

## 本機切分要求

- 原檔取得後，先讀取總頁數；以頁數或輸出檔大小切成可穩定處理的子檔，不改變頁面順序。
- 每個子檔記錄原始頁碼範圍，例如 `part01 = p1-p20`，再逐頁建立文字/影像處理狀態。
- 若只有部分 byte range 或部分頁面成功，仍視為未完整讀取。
- 大型掃描 PDF 無文字層時，分頁轉圖後逐頁視讀/OCR；不可因 OCR 成本高而只抽樣。

## 完整性閘門

每個 PDF 最終必須有：來源 ID、總頁數、每頁處理狀態、抽取方式與申請人邊界。只取得文字摘要或部分頁面不能算完整。任何未讀頁都使整批保持「部分完成」。

## 安全

不可用舊年度資料補當次未讀大型 PDF；不可因檔名相似直接視為同一內容。衍生副本必須用頁數、內容邊界或可驗證資訊確認覆蓋。


## 413 / connector 上限處理

- 若 raw download 明確回報 HTTP 413 或單檔 byte 上限，先記錄實際檔案大小與 connector 回報上限；不要重複使用同一路徑重試，也不要把 413 解讀為檔案損壞。
- 接著依序確認：完整索引文字、可用的已驗證 HTTP Range/串流、同內容分卷/掃描副本、同檔 revisions，以及同一上傳時段可能遺留的原始小檔；每條替代來源都必須可驗證對應原檔與頁面覆蓋。
- 若目前工具沒有登入態 Range/瀏覽器下載能力，必須把該能力缺口與已嘗試路徑記錄在 coverage；仍不得用舊年度或其他申請人的內容補洞。
- 瀏覽器路徑可用時由 Agent 自動下載並切分，不把手動拆檔轉嫁給使用者。只有瀏覽器/Range 也不可用或使用者明確不使用時，才進入 user-split-required，整批維持「部分完成」。
